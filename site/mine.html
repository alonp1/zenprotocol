Mine ZP

ZP uses SHA3-256 proof of work. The repository has a GPU miner (OpenCL: NVIDIA, AMD or Intel) that mines through your own node. Rewards go to any address you own.

What you need

  • A synced node on the same machine: follow Run a node. The node's own CPU miner is not needed (MINER_THREADS=0).
  • A GPU with its normal driver (it includes OpenCL), and Python 3.9 or newer.
  • An address you own, for the rewards: create one in the ZP Wallet. Keep the 24 words offline.

Install and test

pip install pyopencl numpy
cd zenprotocol/miner
python zpminer.py list          # your OpenCL devices
python zpminer.py selftest      # the GPU hashes must equal Python's SHA3-256
python zpminer.py bench         # your hashrate, no node needed
python zpminer.py verify        # rebuilds real mainnet headers from your node and checks their hashes

Run verify once against a synced node before mining.

Mine

python zpminer.py mine --address zen1...your-address

Use --device N to pick a GPU, and run one process per GPU. The node must answer on 127.0.0.1:11567. Block rewards can be spent after 100 blocks.

Rent a server with a GPU

If you have no GPU, you can rent a server that has one, install the node there with the same steps, and run the miner on it. Before you pay:

  • Check the provider's rules. Many cloud providers forbid mining.
  • Measure first. Run bench on a short rental, put the result in the calculator above, and compare the ZP per day with the price of the rental. Mining pays in ZP, so what ZP is worth to you decides whether it makes sense. This page does not promise any profit.

Hashrate rental markets

Marketplaces such as NiceHash rent out hashrate for algorithms they list, and miners connect to a pool through the Stratum protocol. As far as we found, no marketplace lists ZP, and the ZP node has no Stratum pool: the miner above talks to a node directly. So rented hashrate cannot be pointed at ZP today. It would need a Stratum bridge for the node, which does not exist yet.
